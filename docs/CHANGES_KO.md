# 원본 코드 대비 변경 사항

이 fork는 논문 *Retrieval as Reasoning: Self-Evolving Agent-Native Retrieval via LLM-Wiki*
([arXiv 2605.25480](https://arxiv.org/abs/2605.25480))의 공식 코드
([WeAgentAI/LLM-Wiki](https://github.com/WeAgentAI/LLM-Wiki))를 한국어 코퍼스에 적용하기 위해 수정했다.
`WIKI_LANG`을 지정하지 않으면(기본값 `en`) 프롬프트와 검색 동작은 원본과 같다.
아래 1~3절은 원본의 버그나 논문 설명과 다른 부분을 고친 것이라 영어 실행에도 적용된다.

## 1. Error Book: 논문에 설명된 루프대로 동작하도록 수정

논문은 Error Book을 *탐지 → 기록 → 프롬프트 제약 주입 → 다음 생성에서 회피 → 사라졌는지 검증 → 종료*
루프로 설명한다. 원본 코드에서는 이 루프가 다음 이유로 끝까지 돌지 않았다.

| 원본 동작 | 수정 |
|---|---|
| 제약 주입이 단건 프롬프트에만 있어서, 기본값인 배치 모드(`batch_size=3`)에서는 한 번도 주입되지 않음 | 배치 Step 2 프롬프트에도 같은 제약을 주입 (`build_ingest_prompt_batch`) |
| lint에서 이슈가 0건이면 Error Book을 갱신하지 않아 `pass_count`가 증가하지 않음 | 깨끗한 lint도 기록해서 연속 통과 횟수가 증가 |
| LLM 수리 대상 유형 6종(`needs_llm_fix`)은 어떤 경우에도 closed가 되지 않음 | lint에서 2회 연속 탐지되지 않으면 closed. 단 `broken_link`는 LLM이 누락 페이지를 만들 때까지 대기 |
| 다시 탐지돼도 `pass_count`가 초기화되지 않음 | 다시 탐지되면 연속 통과 횟수를 0으로 초기화 |
| 요약·섹션 수리 후에도 샘플이 `fixed: false`로 남음 | 수리한 샘플을 fixed로 표시 |
| broken_link 샘플 키가 서로 달라 같은 링크가 두 번 집계됨 | 링크 대상 기준으로 중복 제거하고, 다시 깨지면 unfixed로 되돌림 |
| Step 1에서 보지 않은 페이지를 덮어쓰려는 시도를 막기만 하고 기록하지 않음 (템플릿은 있으나 미사용) | `unseen_page_overwrite`로 기록 |

추가로 다음을 사람이 볼 수 있게 했다 (동작에는 영향 없음).
- `wiki/error-book.md` 내보내기: 활성·종료 항목, 다음 Step 2 프롬프트에 주입될 제약, 최근 수리 이력.
- `wiki/log.md`: ingest, lint, Error Book 이벤트를 append 방식으로 기록 (카파시 LLM Wiki의 `log.md` 형식).
- 제약을 주입할 때 콘솔 출력. `WIKI_DUMP_PROMPTS=1`이면 프롬프트 전문을 저장.

`ABLATION_ERROR_BOOK=0` 스위치(논문의 ablation)는 그대로 동작한다.

## 2. 실행 경로·호환성 버그

- 벤치마크 경로 불일치를 수정했다. 다운로드는 `llm_wiki_bench/datasets/`에 저장하고, 전처리는 다른 파일명으로 찾고,
  ingest는 레포 루트의 `raw/`에서 읽고 있었다. 이제 모두 레포 루트를 기준으로 한다.
- 데이터셋 이름 하드코딩(hotpotqa/musique/2wikimhqa)을 제거해 임의의 코퍼스 이름을 쓸 수 있다.
- `bench_ingest.main()`의 raw 경로를 `config.RAW_DIR`로 통일했다.
- OpenAI 추론 계열 모델(`gpt-5*`, `gpt-6*`, `o*`)을 지원한다.
  - `max_completion_tokens`와 `reasoning_effort`를 보낸다.
  - 도구 호출은 `reasoning_effort=none`으로 보낸다 (GPT-6 Sol/Luna 요구사항).
- `chat_template_kwargs`(vLLM 전용)는 `LLM_ENABLE_THINKING=1`일 때만 보낸다. 이전에는 OpenAI에 항상 보냈다.
- 재시도해도 소용없는 4xx 오류(잘못된 키·파라미터)는 30초씩 재시도하지 않고 즉시 원인 메시지와 함께 실패한다.
- `configs/wiki-schema.md`를 코드의 실제 검사 기준(digest 4개 섹션, Key Facts/Related Pages/Related Sources)에 맞게
  다시 썼다. 원본 문서는 lint와 다른 섹션 이름을 지시해서, 이를 따르면 영어 실행에서도 lint가 실패했다.

## 3. 매칭 버그

- `_fuzzy_match_article`: 날짜 접두어(`YYYY-MM-DD-`)가 없는 이름도 앞 11글자를 잘랐다.
  유사도 임계값이 0.2로 낮아서, 이름 형식이 같은 문서(예: `…일부개정법률안(…의원 등 10인)`)끼리 잘못 연결됐다.
  날짜 접두어가 있을 때만 자르고 임계값을 0.6으로 올렸다.
- `llm_fix_incomplete_digests`: 파일명의 5번째 글자가 `-`이기만 하면 날짜로 간주했다. 이제 정규식으로 확인한다.

## 3-1. 수리(lint repair) 품질 버그

실제 구축 중 발견해 수정했다.

- **근거 검증이 정상 사실을 대량 삭제하던 문제** (`llm_verify_source_grounding`)
  - 원인: 페이지에 연결된 digest(요약)만 이어 붙이고 앞 3,000자만 근거로 사용했다.
    그래서 출처가 여러 개인 페이지는 대부분의 사실이 "근거 없음"으로 판정돼 삭제됐다
    (small 구축에서 1라운드에 82건 삭제).
  - 수정: 원문 기사(`source_article`)를 근거로 쓰고, 근거 예산을 20,000자로 늘렸다(`GROUNDING_SOURCE_CHARS`).
    근거가 잘린 경우에는 판정을 보류하게 했다.
    또 짧은 문자열 하나가 무관한 사실 여러 줄을 지우지 않도록, 완전히 일치할 때만 삭제한다.
- **페이지를 다시 쓸 때 출처(Related Sources)가 사라지던 문제**
  - 원인: 배치 프롬프트의 "Related Sources: only link digests from this batch" 지시 때문에,
    LLM이 기존 페이지를 갱신하면서 이전 출처 링크를 지웠다.
    예를 들어 법안 페이지에는 나중에 처리된 표결 문서의 출처만 남았다.
    근거 검증은 이 표결 문서와 법안 사실을 대조했고, 문서 154개 구축에서 정상 사실 약 250개를 삭제했다.
  - 수정
    - 프롬프트를 "기존 출처를 유지하고 이번 배치의 digest를 추가"로 바꿨다.
    - 페이지를 덮어쓸 때 빠진 출처 링크를 코드에서 다시 붙인다.
    - 근거 검증에서 한 페이지의 사실 절반 이상이 근거 없음으로 나오면, 출처 불일치로 보고 삭제하지 않는다.
    - LLM이 digest 이름을 잘못 줄여 쓴 링크는 접두어나 ID로 실제 digest에 연결한다.
- **깨진 링크 수리가 깨진 링크를 더 만들던 문제** (`llm_fix_broken_links`)
  - 원인: 누락 페이지를 새로 만들 때 LLM이 존재하지 않는 일반 개념 페이지
    (`[[bills/법안]]`, `[[parties/정당]]` 등)로 링크를 걸어, 라운드마다 깨진 링크가 늘었다(1 → 4 → 12).
  - 수정: 프롬프트에 실제 페이지 목록을 주고, 없는 대상으로 가는 링크는 코드에서 일반 텍스트로 바꾼다.
- **원문 사본의 frontmatter에 `tags`가 없던 문제:** 모든 원문 사본(`sources/articles`)이 lint의 completeness 이슈로
  잡혔는데 auto-fix는 이 디렉터리를 건너뛰어서, 이슈 20건이 영구히 남았다.

- **출처 링크를 지어내던 문제:** LLM이 존재하지 않는 digest(`의안-2210005-…`, 실제 법안은 2200005)나
  잘못 줄인 이름으로 링크를 걸면, 코드 수리와 LLM 수리 모두 `sources/` 링크를 건드리지 않아 lint 이슈가 영구히 남았다.
  - ID, 접두어, 제목 순으로 실제 파일을 찾아 연결한다.
  - 그래도 찾지 못하면 해당 줄을 지우고 수리 이력에 기록한다. digest와 원문 링크 모두에 적용한다.
- **단건 모드(`batch_size=1`)에서 digest 파일명이 어긋나던 문제:** LLM이 digest 이름을 정해서, 원문 연결이 어긋나고
  `.md` 확장자가 빠진 파일이 생겼다.
  - 증분 추가(`add`)도 이름이 고정되는 배치 모드로 처리한다.
  - 모든 출력 파일에 `.md` 확장자를 강제한다.
- **새 문서가 기존 페이지에 반영되지 않던 문제:** Step 1이 관련 기존 페이지(예: 대표발의 의원)를 골라도
  Step 2가 갱신하지 않는 경우가 있었다. 프롬프트에 "새 사실이 있는 기존 페이지도 갱신"을 명시했다.

## 4. 한국어 지원 (`WIKI_LANG=ko`)

원칙: 코드가 검사하는 섹션 제목·frontmatter 키·디렉터리 이름·출력 마커는 영어로 유지하고, 나머지 내용은 한국어로 쓴다.

- **프롬프트**
  - 모든 위키 작성 프롬프트에 출력 언어 지시를 붙인다 (`llm_client.call_llm`).
  - "Use English page names" 대신 공식 한국어 명칭을 쓰고 동명이인은 생년으로 구분하게 했다.
  - 예시를 한국어로 바꾸고, 길이 제한을 단어 수 대신 글자 수로 지정한다.
- **섹션 제목 정규화:** LLM이 `## 핵심 사실`처럼 한국어 제목을 쓰면 `## Key Facts`로 되돌린다.
  그대로 두면 lint↔수리가 무한 반복된다.
- **검색 (`wiki_retriever`)**
  - BM25가 한글을 2글자 단위로 색인한다. 원본 토크나이저는 `[a-z0-9]+`라 한글을 전혀 색인하지 않았다.
  - 조사를 떼어 낸 형태도 점수에 반영한다 (조국혁신당은 → 조국혁신당).
  - 검색어 안에 페이지 이름이 들어 있어도 매칭한다 (김건희특검법 ⊃ 김건희).
- **에이전트:** 한국어 멀티홉 질문의 단서를 인식하고, 한국어 검색 요령을 시스템 프롬프트에 넣었다.
- **답변:** 한국어 답변 프롬프트를 쓰고, "정답:" 같은 접두어를 제거한다.
- **파일명:** NFC로 정규화하고 200바이트(UTF-8)로 제한한다. 한글은 1자당 3바이트라 OS 한도(255바이트)를 넘기 쉽다.
  `/ | # [ ]`를 제거하고, 파일 쓰기에 실패해도 전체 실행이 멈추지 않는다.
- **짧은 이름 매칭:** 2글자 한글 이름이 더 긴 단어 안에서 매칭되지 않는다 (조국 ≠ 조국혁신당, 허영 ≠ 허영심).
- **프롬프트 예산:** 한국어는 같은 글자 수에 토큰이 더 많이 들어서, 프롬프트 예산 기본값을 낮췄다 (환경변수로 조정 가능).

## 5. 사용 편의

- `llm-wiki` CLI, `Makefile`, `.env` 지원, `pyproject.toml`.
- finalize 방식을 선택할 수 있다: `full`(논문 기본: 3라운드), `light`(증분 추가용 1라운드), `none`.
- 국회 데이터 변환기(`corpora/assembly/convert.py`)와 예제 문서(`examples/assembly_spc`).
- Quartz 사이트와 GitHub Pages 배포 스크립트.
  - Quartz로 복사한 사본에서만 H1을 페이지 제목으로 넣는다.
  - github.io 주소에서는 CNAME을 만들지 않는다.
  - 포트를 지정할 수 있다.
  - Quartz를 v5.0.0 태그 대신 v5 브랜치 커밋(플러그인 1.0)으로 고정했다.
    v5.0.0의 그래프·탐색기·검색 플러그인은 `/static/contentIndex.json`과 링크를 도메인 루트 기준으로 만들어서,
    `<user>.github.io/<repo>/` 같은 하위 경로 사이트에서는 그래프가 비고 탐색기·검색 링크가 404가 났다.
  - 코드가 만드는 `_index.md`의 짧은 링크(`[[의안-…]]`)를 사본에서 `[[bills/의안-…]]`로 바꾼다.
    Obsidian은 짧은 링크를 찾아가지만 Quartz는 루트 기준으로 해석해서 384개가 깨졌다.
    홈의 디렉터리 목록도 폴더 페이지 링크로 바꿔 홈 그래프에 연결이 보이게 했다.
- 오프라인 테스트(`tests/`, API 호출 없음).
